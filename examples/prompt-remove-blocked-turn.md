# 交给 Claude 的那段话：把被拦的那一轮带走

为什么要这样做、什么时候别用，在 [README 第 4 节](../README.md#4-被拦以后怎么办)。发之前先做好三件事：

1. 被拦的那个会话已经彻底关掉了：所有终端窗口、套壳的后台、定时消息都停了。
2. 你新开了一个会话：直接输入 `claude`，没带 `-c` 或 `--resume`。
3. 把下面这一整段复制过去发给它。

这段话只处理「普通的一条线」的会话。碰到压缩过、有分叉、对不上号这类拿不准的情况，它会停下来问你。这时候开新会话最省心。

```text
我在另一个 Claude Code 会话里被安全分类器拦下了一轮。我想把那一轮从那个会话的存盘文件里整轮拿掉，再回去接着聊。效果类似回退：把那一轮从对话里拿掉，区别是它后面的对话可以留着。那个会话我已经关掉了。

先说清楚：这只改我电脑上的存盘文件，已经发出去的请求不会撤回；我不会把被拦的内容原样再发，之后的每条消息照样会过安全检查。

为了别让你这边也被拦：读存盘的时候用脚本，只看每一行的 type、uuid、parentUuid、时间，以及下面要用到的几个字段；需要认内容的时候，最多显示前 15 个字；被拦那一轮的内容不用显示。

这段话只处理「普通的一条线」的会话。下面任何一步拿不准，就停下来告诉我，别猜。

请按顺序做。每一步做完告诉我结果，标了「等我确认」的地方停下来等我。

1. 找文件（等我确认）：会话存盘在 ~/.claude/projects/ 下面的各个文件夹里，一个会话一个 .jsonl 文件。只看这一层，子文件夹（比如 subagents/）里的不算。如果设过 CLAUDE_CONFIG_DIR，就去那个目录下的 projects/ 里找。跳过你自己现在这个会话的文件（里面有这段话的那个）。先用 "stop_reason":"refusal" 这串字筛出候选文件，按修改时间从新到旧列最近几个：路径、修改时间、我在里面说的最后一句话的前 15 个字。让我确认是哪一个，别自己挑。

2. 备份：把确认好的文件复制一份，备份的文件名用「原文件名.bak-日期时间」，不要以 .jsonl 结尾，也不要覆盖已经有的备份。记下原文件现在的行数和修改时间。

3. 确认它是一条线（不是就停）：逐行解析。每个 uuid 只能出现一次。从文件里最后一条 type 为 user 或 assistant 的行开始，顺着 parentUuid 往回走：要能一路走到头，中途不断、不绕圈，而且停下的那一行就是文件里最早的那条带 uuid 的记录（停在别处，多半是压缩过或者有分叉）。把这条路上的 uuid 按顺序记下来，下面叫它「改前的链」。

4. 找到被拦的那一轮（等我确认）：
   - 被拦的回复：顶层 type 是 assistant，这一行自己的 message.stop_reason 是 "refusal"，而且在「改前的链」上。只是某段文字里出现了这串字的，不算。
   - 这一轮的开头：从被拦的回复顺着 parentUuid 往回找，找离它最近的一条「我自己说的话」：type 是 user，message.role 是 user，没有 isMeta，内容不是 tool_result，也不是压缩摘要。
   - 如果有 subtype 为 model_refusal_no_fallback 的 system 行，它的 refusedUserMessageUuid 应该就是这一行的 uuid；对不上就停。
   - 文件里不止一处被拦的话，每一处列出时间和我那句话的前 15 个字（同一轮里的几处算一处），让我选；一次只处理一处。

5. 遇到下面任何一种情况，先停下来告诉我，别自己处理：
   - 被拦的那句是这个会话的第一条消息；
   - 这个会话压缩过，或者你看不出有没有压缩过。比如有 subtype 为 compact_boundary 的行、带 isCompactSummary 的行；没看到这两个名字，不等于没压缩过，第 3 步走不到最早那条记录，也算；
   - 那一轮里有工具调用：列出来各做了什么。删了记录也撤销不了它们，删不删由我决定；
   - 要删的范围里有你拿不准属不属于这一轮的行，比如我在它回话的时候插进去的消息；
   - 文件的行数或修改时间，跟第 2 步记下的不一样了。

6. 列出要删的范围（等我确认）：按文件里的行号，从我那句话那一行开始，到我下一句话（按第 4 步同样的标准判断，而且在「改前的链」上）那一行之前；后面没有我说的话了，就到文件末尾。这个范围里 type 为 queue-operation 的行留着，其余整行删掉。范围里每一条带 uuid 的行都必须在「改前的链」上，链上这一段的每一行也都必须落在范围里，哪条对不上就停。按改之前的行号列出要删的行，每一行写类型，不写内容。再列出要接链的那一行：链上紧跟在这一段后面的那一行（通常就是我下一句话那行），它的 parentUuid 要改成我那句话原来的 parentUuid；被拦的是最后一轮、后面没有留下来的行的话，就写明「不用接链」。除了它，如果还有别的行的 parentUuid 指向要删的行，停下来等我确认，不要自己接。

7. 删和接链：我确认以后，写入之前再看一次文件的行数和修改时间，跟第 2 步不一样就停。然后只删第 6 步列出的整行；有要接链的那一行，就只把它的 parentUuid 的值换掉（原来的值是 null 的话，就写不带引号的 null），「不用接链」的就不改任何一行。别把文件整个解析一遍再写回去，那样可能改变转义、空白这些无关的字节；除了换掉的那个值，其他行一个字节都不要动。

8. 检查（不过就恢复）：
   - 每一行都还是合法的 JSON；
   - 跟备份逐行比，差别只有删掉的那几行，加上零处或一处确认过的 parentUuid 修改；
   - 用第 3 步的走法重新走一遍，得到的链必须正好等于「改前的链」去掉删掉的那一段，开头还是同一条。
   哪一项不对，就用备份恢复，再告诉我。

9. 报告：删了第几行到第几行（按改之前的行号）、每一行是什么类型；改了哪一行的 parentUuid，从什么换成了什么；第 8 步三项检查各自的结果。

不要替我重新打开那个会话，我自己来。
```
